# Research: Harden cloudbuild.yaml & Shell Scripts

**Date**: 2026-02-28

## 1. Executive Summary
Research into `cloudbuild.yaml`, `server/scripts/build_python_linux.sh`, and `scripts/cloud_runner_nodejs.py` confirms several security and stability issues. `cloudbuild.yaml` contains broad `find` operations that act as unprotected fallbacks for Node.js builds, potentially bypassing license protection. Shell scripts use inconsistent variable interpolation, and `build_python_linux.sh` has brittle directory traversal logic after changing directories.

## 3. Findings & Analysis

### 3.1 Unprotected Fallbacks
In `cloudbuild.yaml`, the Node.js build step is designed to be "helpful" by searching for any `.exe` if the expected one isn't found.
```yaml
found_exe=$$(find . -name "*.exe" -type f 2>/dev/null | head -1)
```
This is a security risk. The system should strictly package only the artifacts produced and verified by the `cloud_runner_nodejs.py` script, which is responsible for license injection.

### 3.2 Shell Variable Corruption
The ticket mentions `$variable` to `${variable}`. In `cloudbuild.yaml`, shell variables must be escaped with `$$` to avoid Cloud Build interpreting them as substitutions.
Existing correct pattern: `$$linux_status` (Line 183).
Potential issues: Cases where shell-only variables might be interpreted as substitutions or lack braces for clarity.

### 3.3 Broken Directory Traversal in build_python_linux.sh
The script `build_python_linux.sh` changes directory to `./project/source` (Line 37) but then tries to find `build_output_linux` (Line 46). If `cloud_runner.py` was executed with `--source "./project/source"`, it might create `build_output_linux` inside that directory or in the original CWD depending on its internal logic.
Based on `cloud_runner.py` patterns seen elsewhere, it typically creates output relative to the source dir. However, the `find` command is brittle.

## 4. Technical Constraints
- **Cloud Build Syntax**: Must use `$$` for shell variables.
- **Python Formatting**: `server/scripts/build_python_linux.sh` is a template; shell variables must not conflict with Python `{}` placeholders unless escaped.

## 5. Architecture Documentation
The build system relies on a "Builder" image (`codevault-builder`) and runner scripts (`cloud_runner.py`, `cloud_runner_nodejs.py`) to handle the heavy lifting of Nuitka/pkg compilation. `cloudbuild.yaml` orchestrates the environment, caching, and artifact uploading.
