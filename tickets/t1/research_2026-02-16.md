# Research: CLI Refactor - Decouple Compiler Logic

**Date**: 2026-02-16

## 1. Executive Summary
The current CLI compiler logic in `cli/compiler_logic.py` is a monolithic file that tightly couples multiple responsibilities: security validation, license injection, process management, and language-specific compilation (Python/Nuitka and Node.js/Pkg). It uses synchronous and thread-based I/O which is prone to hanging and inconsistent UI updates.

## 2. Technical Context
- **Security Validation**: Functions like `validate_entry_file` (L125), `validate_output_name` (L187), and `safe_resolve_path` (L266) are mixed with compilation logic.
- **License Injection**: `inject_license_wrapper` (L304) for Python and `inject_js_wrapper` (L385) for Node.js use "inline injection," which modifies user source code directly.
- **Process Management**: Uses `subprocess.Popen` with custom thread-based output reading (`_read_output_thread`, L33) and polling loops.
- **Compilation Dispatch**: `run_compiler` (L439) is a simple switch that calls `run_pkg` (L580) or `run_nuitka` (L862).

## 3. Findings & Analysis
- **Concurrency Model**: The CLI relies on `threading.Thread` to read pipe output on Windows to avoid blocking. This is brittle compared to `asyncio`.
- **Node.js Build Strategy**: `run_pkg` performs `npm install` directly in the project directory (L655) and then runs `pkg`. It uses `get_nodejs_wrapper_inline` (L418), which is the problematic "inline" method.
- **Python Build Strategy**: `run_nuitka` (L862) uses standard Nuitka flags but lacks the aggressive "Blacklist" optimizations found in the server-side compiler.
- **UI Integration**: Uses `terminal.py` helpers like `print_progress_bar` (L772) which are manually called during the build loop.

## 4. Technical Constraints
- **Windows Compatibility**: Must handle Windows-specific `subprocess` flags (e.g., `CREATE_NO_WINDOW`, L992).
- **External Dependencies**: Relies on `npx` (L681) for `@yao-pkg/pkg` and `javascript-obfuscator`.
- **Nuitka Environment**: Requires careful environment variable management (e.g., `PYTHONUNBUFFERED=1`, L986).

## 5. Architecture Documentation
The current architecture is **Procedural-Monolithic**. It lacks a clean separation between the "Build Orchestrator" and the "Compiler Implementation." Models for a better architecture exist in `server/compilers/build_orchestrator.py` and `server/compilers/python_compiler.py`.
