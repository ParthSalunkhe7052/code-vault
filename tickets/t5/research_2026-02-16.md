# Research: CLI - Modernize UI with Rich Progress

**Date**: 2026-02-16

## 1. Executive Summary
The CLI already uses a `BuildDashboard` (based on Rich) to display build progress. However, the internal progress bars are manually updated and the logic is fragmented between `build_runner.py` and the compiler functions. The goal is to standardize on `rich.progress.Progress` for smoother, multi-task visualization and integrate it with the new `asyncio`-based compiler classes.

## 2. Technical Context
- **Build Orchestration**: `BuildRunner.run_build` (L165) manages the lifecycle (Prepare, Download, Extract, Inject, Compile, Package).
- **Compilation Monitoring**: `_run_compiler_with_progress` (L245) intercepts compiler output and calls `self.update_phase` (L154).
- **Dashboard UI**: `BuildDashboard` (imported from `codevault_cli.build_dashboard`) provides the layout and update methods.

## 3. Findings & Analysis
- **Phase Mapping**: The build has 6 clear phases. Standardizing these as tasks in a `rich.progress.Progress` instance would allow for a much cleaner UI.
- **Async Integration**: The new `PythonCompiler` and `NodeJSCompiler` emit progress data. The runner needs to pipe this data into the Rich Progress tasks.
- **Simple vs. Rich**: The CLI has a `--simple` flag (default) that uses `simple_build_runner.py`. The "Rich" mode is currently opt-in but should be the target for this modernization.
- **Thread Safety**: Updating Rich UI from multiple async tasks requires careful handling, though standard `Progress` updates are generally safe if managed by the main loop.

## 4. Technical Constraints
- **Terminal Compatibility**: Rich UI can look garbled on very old Windows CMD. We must maintain the `simple` fallback.
- **Nuitka Progress Parsing**: The regex-based parsing from `PythonCompiler` needs to be reliably fed to the Progress bar.

## 5. Architecture Documentation
The `BuildRunner` will be updated to use a `rich.progress.Progress` context manager in its `run_build` method. The compiler classes will accept a callback or a task ID to update progress directly.
