# CLI: Modernize UI with Rich Progress Implementation Plan

## Overview
Standardize the build progress visualization using `rich.progress.Progress`. This will provide a professional, multi-task UI that accurately reflects the build phases and integrates with the new `asyncio`-based compilers.

## Current State Analysis
- `cli/codevault_cli/build_runner.py`: Uses manual `update_phase` calls.
- `PythonCompiler.compile()` and `NodeJSCompiler.compile()`: Have hardcoded `print` statements or basic progress bars.
- Lack of a unified progress tracking context.

## Implementation Approach
1. Update `BaseCompiler` to accept an optional `progress_callback`.
2. Update `PythonCompiler` and `NodeJSCompiler` to use the `progress_callback` for percentage updates.
3. Refactor `BuildRunner.run_build` to use a `rich.progress.Progress` context manager.
4. Map the 6 build phases to specific Rich tasks.

## Phase 1: Compiler Interface Update
### Overview
Add progress reporting capabilities to the compiler classes.

### Changes Required:
#### 1. `cli/compilers/base.py`
**Changes**: Update `compile` signature.
```python
    @abstractmethod
    async def compile(self, progress_callback: Optional[Callable[[int, str], None]] = None) -> Tuple[bool, Optional[Path]]:
        pass
```

#### 2. `cli/compilers/python.py` & `cli/compilers/node.py`
**Changes**: Implement the callback usage.

### Success Criteria:
#### Automated:
- [ ] `python -m py_compile cli/compilers/base.py cli/compilers/python.py cli/compilers/node.py`
#### Manual:
- [ ] Run a build and verify progress data is being emitted via the callback (can use a simple print callback for testing).
