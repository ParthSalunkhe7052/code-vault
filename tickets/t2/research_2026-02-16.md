# Research: Node.js - Implement Bootstrap Wrapping

**Date**: 2026-02-16

## 1. Executive Summary
The goal is to replace the CLI's "inline injection" of license code with a "bootstrap loader" approach. This involves leaving the user's source code untouched and creating a separate entry point that verifies the license before requiring the user's application.

## 2. Technical Context
- **Current CLI Approach**: `inject_js_wrapper` (L385) reads the entry file, wraps it in an async IIFE, and writes it back. This can break ESM imports and makes debugging difficult as it changes line numbers.
- **Server-Side Approach**: `server/compilers/nodejs_compiler.py` uses a superior two-file strategy:
    1. `cv_license_wrapper.js`: Handles license validation logic.
    2. `_cv_bootstrap.js`: A generated file that calls the wrapper and then `require()`s the user's entry point.
    3. `package.json` Modification: Updates the `bin` or `pkg` config to point to the bootstrap file.

## 3. Findings & Analysis
- **Pkg Config**: The server compiler's `_prepare_package_json` (L150) is highly robust. It rglobs for ALL `.js` and `.json` files (L158-175) to ensure they are explicitly included in the `pkg` bundle, which prevents "Cannot find module" errors in complex projects.
- **Bootstrap Content**: The bootstrap loader (L235) uses a `try/catch` and `readline` (L241) to handle errors gracefully and keep the terminal open for user feedback—critical for local CLI usage.
- **Environment Management**: The server uses a temporary build directory (L117) to avoid polluting the user's source tree. The CLI should adopt this "build/" folder convention.

## 4. Technical Constraints
- **Pkg Compatibility**: `pkg` has known issues with certain versions of `axios` and native modules. The server compiler's axios downgrade hack (found in `run_pkg` L618) might still be relevant for local builds.
- **Bundling Warnings**: The server logic tracks bundling warnings (L325) to alert the user if files were missed.

## 5. Architecture Documentation
The current CLI `run_pkg` is monolithic. The new architecture should move this logic into a `NodeJSCompiler` class in `cli/compilers/node.py`, mirroring the `PythonCompiler` refactor.
