# Research: Python - Implement Turbo Mode Optimizations

**Date**: 2026-02-16

## 1. Executive Summary
The goal is to port the server-side "Turbo Mode" optimizations to the CLI's Python compiler. This involves aggressively blacklisting unused or heavy standard library modules during the Nuitka compilation process, which significantly reduces binary size and compilation time.

## 2. Technical Context
- **Current CLI Approach**: Uses a basic list of exclusions (pytest, unittest, etc.) in `run_nuitka` (L862).
- **Server-Side Approach**: `server/compilers/python_compiler.py` implements a two-tier exclusion strategy:
    1. **Standard Blacklist**: Excludes testing, debugging, and rarely used network protocols (L235-265).
    2. **Turbo Exclusions**: Excludes dozens of obscure encodings and compression modules when `turbo_mode` is enabled (L275-315).

## 3. Findings & Analysis
- **Blacklist Modules**: Includes `test`, `unittest`, `pytest`, `pdb`, `doctest`, `trace`, `imaplib`, `poplib`, `smtplib`, `cgi`, `xmlrpc`, `pydoc`, `webbrowser`, `turtle`, `tkinter`, and `curses`.
- **Turbo Exclusions**: Primarily targets the `encodings` package (cp1006, cp1026, etc.) which adds significant overhead to Nuitka's dependency analysis.
- **Plugin Management**: Turbo Mode also disables the `anti-bloat` plugin (L325) for a marginal speed gain, though this should be tested for local compatibility.
- **Parallelism**: The server uses `multiprocessing.cpu_count()` to set `--jobs` (L220), which the CLI already partially implements but should be standardized.

## 4. Technical Constraints
- **Library Dependencies**: Some user projects might actually *need* `tkinter` or `lzma`. The Turbo Mode must be optional (e.g., a flag).
- **Nuitka Version**: These flags are compatible with Nuitka 2.0+, which is our minimum requirement.

## 5. Architecture Documentation
The new `PythonCompiler` class in `cli/compilers/python.py` will incorporate these lists and the logic to apply them based on the `turbo_mode` flag in the build config.
